| Параметр | Значение |

| Маска / шлюз | `255.255.255.0` / `192.168.31.1` |
| MAC | `04-EE-E8-1D-13-94` |

| Режим работы | **TCP Server** |

| Способ получения IP | Static |

**Важно:** прошивка MQTT+JSON **не используется** — она заливается, но публикацию

Веб-страницы настройки восстановлены из официального архива `2043_waveshare_web_zx`.

### Как менять настройки шлюза

```powershell
# посмотреть текущие
python gateway_configure.py

# изменить и применить (шлюз перезапустится)
python gateway_configure.py --set wkm=0 --set lcp=4196
```

Скрипт читает все 24 поля, меняет только указанные, остальные отправляет как есть.
После сохранения **обязательно проверить, что порт 4196 реально слушается** —
сообщение «Success! restart» этого не гарантирует. Если порт закрыт —
повторить отправку (это перезапускает устройство).

### Восстановление настроек из снимка

```powershell
# сверить с эталоном, ничего не записывая (0 = всё совпадает)
python gateway_restore.py --file backup_collector_20261024\gateway_config.txt --verify-only

# восстановить и проверить результат
python gateway_restore.py --file backup_collector_20261024\gateway_config.txt
```

Скрипт записывает **все** поля из снимка, ждёт перезагрузку и **перечитывает
устройство**, сообщая «ГОТОВО: все поля соответствуют снимку» либо список
неприменившихся полей.

> ⚠️ **Главный урок 24.10.2026.** Один раз шлюз остался на `115200` бод в
> прозрачном режиме после серии диагностических переборов — команда возврата
> настроек выполнилась при уже неотвечающем веб-интерфейсе и молча провалилась.
> Из-за этого полтора часа искали «сгоревший RS485», которого не было.
> **Правило: после любых изменений настроек шлюза — прогнать `--verify-only`.**
> Ошибка была не в железе, а в отсутствии проверки результата.

## 1а. Режим MQTT+JSON — автономная публикация шлюзом

Режим, в котором **шлюз сам** опрашивает контроллер и публикует JSON в брокер.
Сборщик и компьютер в цепочке не участвуют.

### Обязательные настройки — все четыре

| Где | Параметр | Значение | Без этого |
|---|---|---|---|
| Device | **Work Mode** | **TCP Client** | MQTT-клиент не запускается вообще |
| Device | **Transfer Protocol** | **None** | Шлюз работает как преобразователь, движок JSON не стартует |
| Device | Destination IP : Port | `158.160.204.124` : `1883` | Нет подключения к брокеру |
| JSON Config | **Upper protocol** | **NONE/MQTT** | Данные не отправляются |
| JSON Config | **Period of send** | > 0 (рабочее 30000) | Отправки не будет никогда |

> ⚠️ **Главное, на чём мы потеряли несколько часов: Transfer Protocol должен быть
> `None`, а не `Modbus TCP to RTU`.** В режиме преобразователя шлюз принимает
> Modbus TCP на порту 4196 и не запускает движок JSON — сколько бы правильным
> ни был дизайн. Симптом: клиент к брокеру подключается, keepalive идёт,
> **публикаций ноль**.

### Порядок перехода в режим MQTT+JSON

1. Vircom → Search → **Restart Dev**.
2. Снова Search → **Firmware/Config** → **web directory download** → папка
   `C:\Users\Saturn\Documents\gateway-mqtt-design`.
3. **JSON Configuration** → «删除全部» → «导入配置» → CSV с дизайном.
   Проверить: число строк соответствует задуманному, **пустых ключей нет**.
4. Выставить **Upper protocol = NONE/MQTT**, **Period of send = 30000**.
5. **MQTT Configuration**: server `158.160.204.124`, port `1883`,
   Client ID `akcc55-gateway`, Publish topic `industrial/sensors/akcc55`, QoS 1.
6. В параметрах устройства: **Work Mode = TCP Client**,
   **Transfer Protocol = None**, Destination `158.160.204.124:1883`.
7. **Save JSON settings** → **Save MQTT settings** → **Download**.
8. Дождаться перезагрузки. Признак успеха: порт **4196 закрывается**,
   в логах Mosquitto появляется `Received PUBLISH from akcc55-gateway`.

### Что происходит с устройством

- **Веб-интерфейс перестаёт открываться** — MQTT-конфигурация заменяет
  веб-страницы настройки. Это нормально, так задумано Waveshare.
- **Порт 4196 закрывается** — режим Modbus TCP↔RTU больше не активен.
- Настройки видны только через Vircom.

### Возврат в режим сборщика (Modbus TCP)

1. Vircom → **Restart Dev** → Search → **Firmware/Config**.
2. **Program File Download** → `gateway_firmware\1.523(2007).BIN` → Download.
3. **web directory download** → `gateway_firmware\web_zx\2043_waveshare_web_zx` → Download.
4. `python gateway_configure.py --set wkm=0 --set lcp=4196 --set ptc=1`
5. `python gateway_restore.py --file backup_collector_20261024\gateway_config.txt`
   (скрипт сам перечитает устройство и подтвердит результат)

### Файлы конфигурации в папке дизайна

| Файл | Что содержит |
|---|---|
| `json` | бинарный дизайн (узлы, адреса) — по ключевым строкам можно проверить, что загружено |
| `mqtt.txt` | **настройки MQTT открытым текстом**: `CLIENT_ID`, `PUBLISH_TOPIC`, `PUBLISH_QOS` |
| `httpd.txt` | настройки устройства, зашифрованы (не читаются) |

### Формат CSV для импорта

Заголовок (23 колонки) копировать из образца экспорта, строки — по 24 поля.
Ключевые значения:

| Поле | Значение |
|---|---|
| Data Source | `Modbus RTU`, `Fixed String` (с заглавной S), `Nested JSON`, `Device ID`, `Current time` |
| Data Format | `Signed int` |
| Modbus Slave Addr. | `1` |
| Modbus Function | `3` |
| Query Period | `100` |

Готовые файлы: `akcc55-mqtt.csv` (21 регистр), `akcc55-mqtt-min.csv` (1),
`akcc55-mqtt-2nodes.csv` (2), `akcc55-mqtt-fixed.csv` (Fixed String для проверки).

## 2. Контроллер Danfoss AK-CC55 Compact

| Параметр | Значение |
|---|---|
| Модель | **AK-CC55 Compact**, код заказа `084B4081` |
| Адрес Modbus | **1** (`o03 = 1`) |
| Формат кадра | 9600 8E1 |
| Адресация | **адрес = PNU − 1**, функция **0x03** |

**Текущие уставки (мы их меняли):**

| Параметр | Адрес | Значение |
|---|---|---|
| `r00` уставка (Cutout) | 99 | **5.0 °C** (сырое 50) |
| `r02` макс. ограничение уставки | 101 | **5.0 °C** (было 3.4 — поднимали, чтобы стало возможным 5.0) |
| `r03` мин. ограничение | 102 | −30.0 °C (не менялось) |
| `r01` дифференциал | 100 | 3.1 K |

**Датчики:** S3 подключён (показывает ~23 °C), S2 / S4 / испаритель отсутствуют —
их значения в базе превращаются в `null`, флаг `S2 error` активен, суммарная авария = 1.

**Адрес `0` запрашивать нельзя** — вернёт исключение `0x02 ILLEGAL DATA ADDRESS`.

## 3. Сборщик телеметрии

**Файл:** `collector.py` (зависимостей нет, чистый Python 3.14)

```powershell
python collector.py --interval 30
```

| Параметр | Значение |
|---|---|
| Контроллер | `192.168.31.200:4196`, слейв 1, режим `tcp` (Modbus TCP) |
| Брокер | `158.160.204.124:1883` |
| Топик | `industrial/sensors/akcc55` |
| Client ID | `akcc55-collector` |
| QoS | 1 |
| Период | 30 секунд |
| Регистров | 21 |

**Готовый запуск:** двойной щелчок по `run_collector.cmd`.

**Полезные флаги:** `--once` (один цикл), `--simulate` (без шлюза),
`--mode rtu` (если шлюз перевести в прозрачный режим).

> ⚠️ **Не запускать два экземпляра одновременно** — строки будут дублироваться.

## 4. Сервер в Yandex Cloud

| Что | Значение |
|---|---|
| ВМ | **`158.160.204.124`** (Yandex.Cloud, Москва) |
| Домен | `industrial-telemetry.ru` → этот же адрес |
| SSH | алиас `yc-vm`, пользователь `mit-2`, ключ `~/.ssh/keys/yc-vm-key` |
| Брокер | Mosquitto в контейнере `it-mosquitto`, порт **1883**, `allow_anonymous true` |
| Хранитель | контейнер `it-keeper`, подписка `industrial/sensors/#`, health `:3100/health` |
| База | PostgreSQL в `it-kratos-db`, база **`telemetry`**, пользователь `kratos` |
| Таблица | `telemetry(id, ts, device, topic, payload JSONB)` |

**Схема сообщения:** сборщик публикует плоский JSON с ключами
`pe, s2, s3, s4, s5, setpoint, diff, main_switch, air_temp, evap_temp, food_temp,
s2_temp, s3_temp, s4_temp, s5_temp, reg_state, eev_opening, pwm_od, alarm_sum,
alarm_high_temp, alarm_low_temp` + `device` + `gateway`.

Блок `gateway` читается со страницы шлюза при старте сборщика:

```json
"gateway": {"ip": "192.168.31.200", "mac": "04-EE-E8-1D-13-94",
            "name": "000000001", "firmware": "1.523"}
```

MAC на странице шлюза лежит в отдельной ячейке таблицы (`<td>Device MAC</td><td>04-EE-…</td>`),
поэтому парсится поиском самого шаблона адреса, а не по подписи.

Хранитель нормализует: флаг ошибки датчика → связанные температуры `null`,
температура вне −100…150 °C → `null`.

## 6. Грабли, на которые уже наступали

| Грабли | Как есть |
|---|---|
| Чётность | Должна быть **Even**. С `None` контроллер молчит полностью |
| База адресов | `PNU − 1`. Уставка `r00` = адрес **99**, а не 100 |
| Ограничение уставки | `r02` не даёт поставить больше своего значения. Поднимать `r02`, затем `r00` |
| Порт 4196 | После правки настроек может не подняться — пересохранить конфигурацию |
| Первые чтения | Сразу после перезапуска шлюза возможен таймаут — повторить |
| Прошивка MQTT+JSON | Публикацию не начала; откатили на V1.523 |
| Веб-интерфейс | После смены прошивки «умирает» — восстанавливается архивом `2043_waveshare_web_zx` |
| Два сборщика | Дают дубли строк в базе |
| Точка входа | Сборщик в фоновом процессе умирает вместе с сессией — для постоянной работы нужен `run_collector.cmd` |
